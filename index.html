01

Cowork Autonomous multi-agent pipeline

WiseForge · automation.byheir.com

Built
Built and operate a 24/7 pipeline of 16 role-specialized LLM agents (spec writers, implementers, security and architecture reviewers, testers, a final ship/hold gate) across 5 parallel lanes on Claude Code and the OpenAI API.
Control layer
Designed the control layer that lets it act on its own: 3 reviewer agents vote independently, and a change ships only with unanimous approval, passing checks and room under a daily cap. An emergency stop freezes it after 2 human reversals in 24 hours.
Measured
0% of auto-approved changes were reverted during the controlled ramp, with every decision’s rationale logged for audit. Instrumented every action as structured logs and classified recurring failures, then ranked and shipped 8 fixes from that audit, lifting productive capacity from 9.2% to 30%+ — and published what the numbers do not prove.
  • Claude Code
  • OpenAI API
  • 16 agents
  • 5 lanes
  • Node.js

04 Approach

Designed like it has to pass an audit

I design the way I engineer: for people making high-stakes decisions under time pressure, in systems where reliability and data integrity are non-negotiable.

  1. i.

    Hierarchy before decoration

    Every screen starts from the decision it supports — the KPI, the exception, the next action — and the layout follows from that.

    Operations Command Center case study →
  2. ii.

    Systems, not screens

    Five domain suites and 49 screens — collections, fraud, credit, servicing, education — built on one set of patterns: hub, queue, case, export.

    Operations Dashboard →
  3. iii.

    Designed in the medium

    I prototype in code, so what you review is what ships — real states, real data, real breakpoints. Functional demos, not mockups.

    SQL Playground →
  4. iv.

    Trust is a design material

    Audit trails, policy citations, guardrails, and human approval are part of the interface — not something bolted on after the build.

    LoanOps Agent Control Plane →
