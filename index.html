02

Cowork Autonomous software pipeline

Sole architect · automation.byheir.com

Problem
“AI-assisted coding” workflows still require a human in the loop for spec authoring, review, merge decisions, and recovery from agent failures — the orchestration is the work.
Approach
Shipped a fully autonomous pipeline of 16 role-specialized agents (spec authors, multiple reviewers, persona playtesters, vision keeper) coordinating across 5 parallel lanes, each scheduled by launchd and picking work from a domain-allocated sprint plan.
Decision
Autonomy lives behind the constraints — auto-gate with 3-agent voting, daily merge caps, blocked-path allowlists, emergency-stop on consecutive reverts, and a public demo with a redaction layer over the same instance the system runs on.

  • Vanilla JS
  • Tailwind
  • Chart.js

04 Approach

Designed like it has to pass an audit

I design the way I engineer: for people making high-stakes decisions under time pressure, in systems where reliability and data integrity are non-negotiable.

  1. i.

    Hierarchy before decoration

    Every screen starts from the decision it supports — the KPI, the exception, the next action — and the layout follows from that.

    Operations Command Center case study →
  2. ii.

    Systems, not screens

    Five domain suites and 49 screens — collections, fraud, credit, servicing, education — built on one set of patterns: hub, queue, case, export.

    Operations Dashboard →
  3. iii.

    Designed in the medium

    I prototype in code, so what you review is what ships — real states, real data, real breakpoints. Functional demos, not mockups.

    SQL Playground →
  4. iv.

    Trust is a design material

    Audit trails, policy citations, guardrails, and human approval are part of the interface — not something bolted on after the build.
